Process

Development Workflow

A disciplined, repeatable workflow I follow on every Laravel project — no shortcuts, no skipped steps.

Migration → Model → Factory → Seeder → Policies & AppServiceProvider → Middleware & bootstrap/app → Controller → Routes → Blade Views
Step 1 Migration
database/migrations/
Naming Convention
2025_01_01_000000_create_{table}_table.php
What I Define
  • up() — creates the table with columns, foreign keys, indexes
  • down() — drops the table (reversible migrations)
  • Appropriate column types with string lengths
  • Foreign key constraints with onDelete behaviour
  • softDeletes() on every table
  • Status fields default to 'pending' with options: pending, approved, rejected
Step 2 Model
app/Models/
Required Elements
  • $fillable — defined on every model (mass assignment protection)
  • $casts — attribute casting where possible
  • getXxxOptions() — method for every enum-like field (returns plain English options array)
  • SoftDeletes trait — on every model
  • Relationships — all used relationships defined (belongsTo, hasMany, etc.)
  • $timestamps = true — unless the table truly lacks them
Step 3 Factory
database/factories/{Model}Factory.php
What I Define
  • definition() — default fake data using Faker
  • state() methods — for variations (e.g., approved(), rejected())
  • has() and for() — for related models
Step 4 Seeder
database/seeders/
Rules I Follow
  • Idempotent — use truncate(), upsert(), or firstOrCreate() (no duplicates on re-run)
  • Foreign key order — call seeders respecting dependencies (users before posts)
  • Development only — seeded data never runs in production
Step 5 Policies & AppServiceProvider
app/Policies/ · app/Providers/AppServiceProvider.php
Policy Methods (every model)
index, show, create, store, edit, update, destroy, restore, forceDelete
What I Check in Policies
  • Ownership — user.id matches model.user_id
  • Role-based access — isAdmin(), isStaff()
  • Custom business rules
AppServiceProvider Registration
  • Register all policy mappings
  • Set up Gate::guessPolicyNamesFor() for automatic resolution
Step 6 Middleware & bootstrap/app
app/Http/Middleware/ · bootstrap/app.php
Required Middleware (PascalCase + Middleware suffix)
  • IsAdminMiddleware — role:isAdmin access
  • IsStaffMiddleware — role:isStaff access
  • IsUserAccessAllowed — foreign key matches auth()->user()->id
Registered in bootstrap/app.php
  • Alias 'role:isAdmin' → IsAdminMiddleware::class
  • Alias 'role:isStaff' → IsStaffMiddleware::class
  • Alias 'user.access' → IsUserAccessAllowed::class
Step 7 Controller
app/Http/Controllers/
Standard Methods (every controller)
index, create, store, show, edit, update, destroy, restore, forceDelete
My Controller Pattern (Thin Controllers)
  • Authorize — $this->authorize() using Policies
  • Validate — $request->validate() at the start of each method
  • Execute — perform the action (delegate complex logic to Services)
  • Redirect — with flash message
  • Implicit route model binding — used always
Step 8 Routes
routes/web.php
Rules I Follow
  • Always use named routes — ->name() on every route
  • Never use Route::resource() — individual routes only (explicit > implicit)
  • Group related routes with Route::group() or Route::prefix()
  • Apply 'auth' and 'verified' middleware to protected routes
  • Apply 'role:isStaff' or 'role:isAdmin' as needed
  • Add restore (staff) and forceDelete (admin) routes for soft-deleted models
Step 9 Blade Views
resources/views/
View Structure (per feature)
posts/ ├── index.blade.php # List all posts ├── show.blade.php # Single post ├── form.blade.php # Handles BOTH create AND edit in one file └── partials/ └── post-card.blade.php partials/ ├── modals/ │ ├── modal-delete.blade.php │ ├── modal-restore.blade.php │ └── modal-force-delete.blade.php ├── alerts/ │ ├── success.blade.php │ └── error.blade.php └── form-group.blade.php # Reusable form elements
Blade Rules I Follow
  • Use @directives throughout (@if, @foreach, @can, etc.)
  • {{ }} for output (auto-escaped)
  • {!! !!} only for trusted HTML — never raw user input
  • Authorization: @can / @cannot directives only — no @php auth checks in views
  • Avoid @php directives — move logic to controller
  • Hardcode English strings directly in Blade (no translation files)
  • Never use text-muted, small, or bg-* classes in Blade — all styling in CSS
